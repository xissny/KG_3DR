# 课程概念与实现对照

## 1. 知识图谱与本体

三元组例如“方法A—采用—全局注意力”。Neo4j节点代表实体，带类型的边代表关系。本体规定关系两端允许的实体类型；例如方法使用组件不能写成数据集使用论文。

`models.py`定义约束，`review/service.py`归一实体，`graph/store.py`执行Cypher。训练与评测关系分开，避免失去语义。

## 2. 信息抽取与证据

大模型负责从原文提出候选，不直接提供真值。正则/结构校验只能检查格式；证据匹配只能检查引文是否存在；是否准确表达论文结论需要人工确认。

页码统一使用PDF页序号，不一定等于论文印刷页码。文件哈希防止证据指向被替换的PDF。

## 3. 图谱自动分类与高级分类实验

日常分类不需要人工金标准。系统以正式图谱中属于目标论文的事实为依据，自动整理研究主题、方法类型、任务类别，再进行明确任务关系归类和DeepSeek语义推断。每个维度允许多个类别或信息不足。共享实体和引用关系不转移事实归属，模型输出只能使用给定类别及目标论文证据；引用检查不等于语义证明。结果、类别及可选用户修订单独存放，不覆盖下面的实验。

### 高级监督学习实验

一篇论文可涉及多个任务，故用多个二元逻辑回归模型。

- 构造去标签的无向特征图。
- 计算一跳/二跳邻域的实体ID指示与类型计数。
- 每折用DictVectorizer把训练字典转为稀疏矩阵。
- 对每个任务估计概率，阈值固定0.5。
- Micro-F1汇总所有预测，Macro-F1对各类等权平均。

留一交叉验证每次只留一篇用于测试。特征图采用已知无标签结构，属于传导式设定，不等同于完全新论文的归纳测试。不能把任务节点、标签边、它们的派生统计或带答案的文本放进特征。

## 4. 关系预测

### 日常缺失关系发现

网页默认扫描正式图谱，也可选择源实体。支持使用组件、解决任务、输出表示、训练数据集、评测数据集和使用指标六类关系，按本体限制两端类型，排除已有三元组和无支持路径的候选。每个源实体的每类关系保留路径分数最高的10条，同分按实体ID稳定排列。

路径使用六类关系及PROPOSES，沿无向简单节点路径搜索2/3跳，不使用CITES；平行关系不重复增加节点路径分数，但解释保留原始边方向及证据。最多展示5条路径，全部路径参与计分。分数不是概率，路径原文不能直接证明预测关系成立；结果只供核验，不写入正式图谱。

最近成功结果保存为 `experiments/relation_prediction.json`，刷新和清理运行记录不会删除它。旧版本结果使用当时的解释快照并提示重新预测；静态导出可浏览和筛选，不能发起计算或打开服务器PDF。

接口：`POST /api/run`，请求示例 `{"stage":"relation_predict","source_id":null,"relation_types":["USES_COMPONENT","SOLVES"]}`。源实体省略或为null时扫描全图，关系类型省略或为null时使用六类全选，空列表和不支持的关系类型返回400。结果通过 `/api/state` 的 `results.relation_prediction` 获取。

### 高级组件关系评测

删除“方法—使用组件”的目标组，从剩余结构寻找支持路径：

`score = 二跳路径数 + 0.5 × 三跳路径数`

频率基线直接按组件在训练边中出现次数排序。filtered评测过滤同一方法的其他已知正确组件。若有并列，平均秩为：

`rank = 1 + 分数更高候选数 + (同分候选数 - 1)/2`

MRR是倒数排名的均值。条件MRR只在候选可覆盖目标上计算；同时报告覆盖率与把不可覆盖目标计为0的端到端MRR。

## 5. 图谱增强生成

实体匹配与固定Cypher先取回事实，再组织DeepSeek提示。模型输出每条结论关联事实和证据ID。代码验证这些ID存在、且证据确实属于引用事实，但不能自动证明整句语义受到支撑。

因此正式评价需要人检查回答正确性、引文正确性、证据支持与无依据内容。找不到实体、事实不足时应返回不足说明。
